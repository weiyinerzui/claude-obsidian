# 高手的黑箱第4讲应用阶段总结

## 当前学习位置

我们已经从第 3 讲「理解」进入第 4 讲「应用」。

第 3 讲解决的问题是：

```text
我是否看懂了知识的结构？
```

第 4 讲解决的问题是：

```text
这个结构能不能进入现实，改变行动？
```

核心转折是：

```text
理解不是终点。
知识必须进入具体处境、变量、阻力、工具和反馈，才算开始应用。
```

---

## 一、应用的基本问题

用户指出自己的困难是：

```text
我知道一些模型，但是仅限于理论或概念的学习，没有经过训练，遇到问题想不起来使用模型。
```

这个问题被重新定义为：

```text
不是没有模型，而是模型没有进入调用层。
```

也就是说，模型目前还停留在：

```text
知识库
```

没有进入：

```text
行动触发器
```

关键判断：

```text
模型是按名称存的，但现实问题不是按名称出现的。
```

脑子里存的是：

```text
GROW
WOOP
SWOT
图尔敏
SCQA
```

但现实出现的是：

```text
拖延
卡住
说不清
选择困难
关系冲突
行动失败
```

所以应用训练的方向不是：

```text
模型 -> 定义
```

而是：

```text
问题场景 -> 可调用模型
```

---

## 二、模型应用卡

为了让模型从概念进入行动，我们提出了「模型应用卡」。

一个模型要能被用出来，至少要经历三次转换：

```text
理论模型
  -> 场景识别
  -> 提问模板
  -> 行动步骤
```

后来进一步修正为：

```text
理论模型
  -> 适用场景
  -> 入口信号
  -> 核心问题
  -> 最小动作
  -> 首次试用场景
  -> 复用触发点
  -> 使用后反馈
```

最终版模板：

```text
模型应用卡

1. 模型名称
2. 适用场景
3. 入口信号
4. 核心问题
5. 最小动作
6. 首次试用场景
7. 复用触发点
8. 使用后反馈
```

前 5 项负责：

```text
让模型能被理解和调用。
```

后 3 项负责：

```text
让模型不会变成死笔记。
```

核心判断：

```text
如果一个模型不能被改写成“什么时候用”和“问什么问题”，它就还没有进入应用状态。
```

---

## 三、结构化知识

第 4 讲区分了两类能落地的知识：

```text
高度抽象的结构化知识
高度具体的菜谱型知识
```

结构化知识的作用是：

```text
把混乱问题转化成有顺序的问题。
```

它不是直接给答案，而是给一组该问的问题。

例如：

```text
GROW
WOOP
SWOT
SCQA
AIDA
图尔敏论证模型
波特五力
第一性原理
```

这些模型的价值不在于名字，而在于它们能把现实问题重新组织。

结构化知识要落地，需要经历三次翻译：

```text
第一次翻译：从模型名到适用问题
第二次翻译：从适用问题到入口信号
第三次翻译：从模型结构到核心问题
```

应用公式：

```text
模型应用 = 适用场景 + 入口信号 + 核心问题 + 最小动作
```

---

## 四、GROW 模型

GROW 是一个教练式推进模型。

它最适合的场景是：

```text
我想推进一件事，但不知道下一步。
事情卡住了，脑子里都是想法，但没有行动。
```

GROW 四个部分：

```text
G = Goal：目标
R = Reality：现实
O = Options：选项
W = Will：意愿 / 行动承诺
```

GROW 应用卡：

```text
模型：
GROW

适用场景：
我想推进一件事，但不知道下一步。
事情卡住了，脑子里都是想法，但没有行动。

入口信号：
“好乱。”
“不知道怎么办。”
“先放着吧。”
“等我想清楚再说。”
“我好像一直在原地打转。”

核心问题：
G：我真正想达成什么？
R：现在真实情况是什么？
O：我有哪些可能做法？
W：我愿意先做哪一步？

最小动作：
用 10 分钟写下：
1 个目标
3 条现实情况
3 个可选动作
1 个 24 小时内能完成的下一步
```

用户指出 GROW 中最有用的是：

```text
落实到一个愿意执行的下一步。
```

于是重点转向 Will。

Will 的本质不是决心，而是：

```text
行动落点。
```

一个合格的 Will，要满足四个条件：

```text
具体
小
有时间
能完成
```

Will 检查表：

```text
1. 它是不是一个动作？
   不是态度，不是愿望，不是方向。

2. 它是不是足够小？
   5 到 30 分钟内可以完成。

3. 它有没有时间和地点？
   今天什么时候，在哪里做？

4. 它有没有完成标准？
   做到什么就算完成？

5. 它是不是我愿意做的？
   不是理论上应该，而是我真的愿意先做。
```

GROW 的关键句：

```text
不要问我该做什么，问我愿意先做哪一个小动作。
```

## 五、WOOP 模型

WOOP 和 GROW 都用于把想法带入行动，但处理的问题不同。

```text
GROW：
事情卡住了，不知道下一步。

WOOP：
我知道自己想做什么，但总是做不到。
```

WOOP 四个部分：

```text
W = Wish：愿望
O = Outcome：结果
O = Obstacle：障碍
P = Plan：计划
```

WOOP 应用卡：

```text
模型：
WOOP

适用场景：
我有一个愿望或目标，但过去反复没有行动，或者开始后容易中断。

入口信号：
“我真的想做，但总是拖。”
“我每次都开始不了。”
“我知道这件事重要，但就是没动。”
“我又失败了。”
“我总是在同一个地方卡住。”

核心问题：
Wish：我真正想实现的愿望是什么？
Outcome：如果实现了，最好的结果是什么？
Obstacle：我内在最大的障碍是什么？
Plan：如果这个障碍出现，我就怎么做？

最小动作：
写下一个愿望、一个好结果、一个内部障碍、一句 if-then 计划。
```

WOOP 的关键不是正能量，而是：

```text
提前看见什么会阻止我行动。
```

它的核心机制：

```text
愿望
  -> 激活动机

好结果
  -> 让愿望变得有吸引力

障碍
  -> 看见现实阻力

if-then 计划
  -> 预先设置应对动作
```

WOOP 的关键句：

```text
把失败点提前纳入计划。
```

## 六、用户识别出的关键障碍

在用 WOOP 训练「模型应用卡」时，用户选择的内部障碍是：

```text
B. 写完后不复用，变成又一份笔记。
```

这说明真正的问题不是：

```text
做不出应用卡。
```

而是：

```text
应用卡没有进入使用场景。
```

于是我们用 WOOP 重新设计：

```text
Wish：
做出几张真正能被调用的模型应用卡。

Outcome：
遇到卡住、拖延、说服、写作等问题时，我能立刻找到一个模型来推进，而不是只靠感觉硬扛。

Obstacle：
应用卡写完后，被放进笔记里，不再被打开。它变成“我整理过的知识”，而不是“我正在使用的工具”。

Plan：
如果我写完一张应用卡，我就立刻给它绑定一个真实使用场景，并安排一次 10 分钟试用。
```

核心修正：

```text
卡片完成 ≠ 学习完成
卡片被使用一次 = 学习开始进入应用
```

进一步形成 if-then 计划：

```text
如果我写完一张模型应用卡，
我就立刻补上：
1. 第一次什么时候用？
2. 哪个现实信号会提醒我复用？
3. 用完后记录一句反馈。
```

## 七、菜谱型知识

进入第 4 讲下一步：菜谱型知识。

结构化知识回答：

```text
我该怎样理解这个问题？
```

菜谱型知识回答：

```text
我现在具体怎么做？
```

两者区别：

```text
结构化知识像地图。
菜谱型知识像路线。
```

菜谱型知识的价值：

```text
把专家已经摸索过的隐性动作，转写成新手可以执行的外显程序。
```

它有五个要素：

```text
步骤
顺序
工具
判断标准
常见错误
```

---

## 八、模型应用卡的菜谱

菜谱：制作一张模型应用卡

```text
目标：
把一个理论模型改造成现实中可调用的工具。

材料：
一个模型
一个常见问题场景
一个 Markdown 模板或纸笔

步骤：
1. 写模型名称。
2. 用一句话写：什么时候用它？
3. 写 3 个入口信号：现实中出现哪些话、感觉、卡点时，该想起它？
4. 把模型结构改写成 3 到 6 个问题。
5. 写一个 5 到 15 分钟内能做的最小动作。
6. 写第一次试用场景：什么时候第一次用？
7. 写复用触发点：以后什么信号出现时再打开？
8. 用完后记录一句反馈：它有没有推进现实行动？

完成标准：
每栏至少一句话。
最小动作不超过 15 分钟。
首次试用场景必须具体。
复用触发点必须来自真实语言或真实卡点。

常见错误：
不要写成长篇理论笔记。
不要追求完整。
不要只收藏不试用。
不要把最小动作写成宏大计划。
不要跳过反馈。
```

这就是菜谱型知识：它不再解释模型是什么，而是规定怎么做。

## 九、本阶段核心结论

### 1. 应用不是整理知识，而是改变行动

```text
知识被整理了，不等于知识被应用了。
```

应用必须进入：

```text
场景
动作
试用
反馈
修正
```

### 2. 模型需要反向索引

不是：

```text
模型 -> 定义
```

而是：

```text
问题场景 -> 模型 -> 操作步骤
```

### 3. 模型应用卡是结构化知识进入现实的桥梁

它让模型从理论变成工具：

```text
适用场景
入口信号
核心问题
最小动作
首次试用
复用触发
使用反馈
```

### 4. 菜谱型知识防止模型卡在概念层

结构化知识帮助看清问题。

菜谱型知识帮助穿越执行。

两者接起来才是应用闭环：

```text
问题场景
  -> 选择模型
  -> 填写应用卡
  -> 安排首次试用
  -> 使用后反馈
  -> 修正模型
```

### 5. 不要把知识管理误认为知识应用

```text
记忆：
让知识能被保存和重新找到。

应用：
让知识能在现实中改变动作。
```

## 下一步共读入口

下一步进入第 4 讲更大的框架：

```text
知行显隐四象限
```

它解释为什么知识落地这么难：

```text
有些东西知道了也做不到。
有些东西做得到却说不清。
```

也就是两道屏障：

```text
知与行的屏障
显与隐的屏障
```
