# 高手的黑箱第4讲知行显隐阶段总结

## 当前学习位置

本阶段继续推进第 4 讲「应用」。

上一阶段已经讨论了：

```text
结构化知识
菜谱型知识
模型应用卡
GROW
WOOP
```

本阶段进入更大的框架：

```text
知行显隐四象限
```

它解释为什么知识落地这么难。

核心判断：

```text
应用不是简单地“知道一个知识点”。
应用是理论、程序、体认、能力之间的往返转化。
```

---

## 一、知识落地的两道屏障

第 4 讲指出，知识落地要跨过两道屏障：

```text
知与行的屏障
显与隐的屏障
```

### 1. 知与行的屏障

有些东西知道，但做不到。

例如：

```text
我知道要早睡，但还是熬夜。
我知道要运动，但还是不动。
我知道模型要应用，但还是只收藏。
我知道写作要具体，但还是写抽象判断。
```

这类问题不是知识不足，而是：

```text
知识没有变成行动路径。
```

它卡在：

```text
知 -> 行
```

### 2. 显与隐的屏障

有些东西会做，但说不清。

例如：

```text
高手知道一句话哪里别扭，但说不清完整规则。
厨师知道火候到了，但新手看不出来。
写作者知道这个开头没气，但很难公式化说明。
设计师知道这里不高级，但不一定能完整解释。
```

这类知识不是显性的规则，而是隐性的判断。

它卡在：

```text
隐 -> 显
```

---

## 二、知行显隐四象限

一条轴是：

```text
知 / 行
```

另一条轴是：

```text
显 / 隐
```

四象限如下：

```text
                 显性
                  |
                  |
        理论      |      程序
      知道什么    |    怎么操作
                  |
知 ---------------+--------------- 行
                  |
        体认      |      能力
      感到什么    |    会做什么
                  |
                  |
                 隐性
```

也可以压缩成：

```text
显性 + 知 = 理论
显性 + 行 = 程序
隐性 + 知 = 体认
隐性 + 行 = 能力
```

这四个词是本阶段核心：

```text
理论
程序
体认
能力
```

---

## 三、理论：显性的知

理论是说得清的知识。

例如：

```text
GROW 有四步。
WOOP 包含愿望、结果、障碍、计划。
认知负荷来自工作记忆容量限制。
图尔敏模型包括主张、理由、依据、支撑、限定、反驳。
```

理论的优点：

```text
可表达
可传播
可检索
可复习
```

理论的问题：

```text
知道不等于做到。
```

因此，理论不能直接等于能力。

---

## 四、程序：显性的行

程序是能说清步骤的行动知识。

例如，制作模型应用卡的程序：

```text
1. 写适用场景
2. 写入口信号
3. 写核心问题
4. 写最小动作
5. 写首次试用
6. 写复用触发
7. 写使用反馈
```

程序比理论更接近应用。

它把：

```text
我知道
```

推进到：

```text
我可以照着做
```

菜谱型知识主要位于这个象限。

---

## 五、体认：隐性的知

体认是心里明白，但很难完全说清的东西。

例如：

```text
我终于感到“此刻不结算人生”是什么意思。
我知道自己为什么会把未回复理解成不重要。
我体会到模型不是答案，而是一组问题。
我感觉到一个表达哪里不真诚。
```

体认不是纯理论。

它带有：

```text
经验
感受
生命处境
现实触动
```

体认不能靠别人解释直接获得。

它需要：

```text
知识和自己的真实经验对上。
```

---

## 六、能力：隐性的行

能力是会做，但未必说得清。

例如：

```text
高手写作时自然知道哪里该删。
教练能听出对方真正卡在哪里。
厨师凭手感判断火候。
程序员一眼看出代码哪里味道不对。
读者能感觉一段论证哪里跳了。
```

这就是「高手的黑箱」。

很多真正厉害的能力，最后都会有隐性部分。

它们可以训练，可以靠近，但不能完全化约成规则。

---

## 七、知识落地的真实路径

知识应用不是简单地从理论到行动。

它至少包含几种转化：

```text
理论 -> 程序
理论 -> 体认
程序 -> 能力
体认 -> 能力
```

可以画成：

```text
[理论]
  --菜谱化-->
[程序]

[理论]
  --经验化-->
[体认]

[程序]
  --反复练习-->
[能力]

[体认]
  --行动验证-->
[能力]
```

核心判断：

```text
知识要落地，必须在四象限之间移动。
```

如果只停在理论，它是空的。

如果只有程序，没有体认，它是机械的。

如果只有体认，没有程序，它容易散。

如果只有能力，却不能部分显化，它很难传给别人，也很难复盘改进。

---

## 八、用模型应用卡解释四象限

以「模型应用卡」为例。

### 理论层

```text
模型应用 = 适用场景 + 入口信号 + 核心问题 + 最小动作 + 试用反馈
```

这是理论。

### 程序层

```text
打开模板。
填写 8 栏。
每栏一句话。
写完安排首次试用。
用完记录反馈。
```

这是程序。

### 体认层

```text
我突然明白：
如果没有首次试用，卡片只是笔记；
只有进入现实循环，它才是工具。
```

这是体认。

### 能力层

```text
以后我学任何模型时，
会自然问：
它什么时候用？
现实中什么信号会提醒我？
最小动作是什么？
怎么试用？
```

这是能力。

---

## 九、AI 在四象限中的作用

AI 很擅长帮助两类转化：

```text
1. 把理论转成程序
2. 把隐性体认尝试外显化
```

例如：

```text
我知道 GROW，但用不起来。
```

AI 可以帮助转成：

```text
模型应用卡模板
使用步骤
最小动作
复用触发点
```

这是：

```text
理论 -> 程序
```

再例如：

```text
我觉得这段话不真诚，但说不清。
```

AI 可以追问：

```text
是不是太抽象？
是不是没有具体场景？
是不是用了过度概括？
是不是缺少代价和犹豫？
```

这是尝试把：

```text
隐性体认 -> 显性语言
```

但 AI 不能替代全部过程。

边界是：

```text
AI 可以帮助显化，但不能替代体认。
```

它可以生成模型应用卡，但人仍然需要：

```text
使用
反馈
修正
练习
```

---

## 十、用户识别出的缺口：体认与能力

用户判断自己在「模型应用」这件事上最缺的是：

```text
体认与能力
```

这意味着：

```text
不是缺理论。
也不只是缺步骤。
而是缺少真实使用中的明白，和反复使用后的自然化。
```

换句话说，当前学习已经过了：

```text
知道
整理
理解
```

真正要进入：

```text
使用中的明白
反复使用后的自然调用
```

---

## 十一、体认如何产生

体认不是别人告诉你：

```text
GROW 有用。
WOOP 有用。
模型应用卡有用。
```

而是你在真实场景里亲自感到：

```text
原来它真的把我从混乱里拉出来了。
原来我不是缺努力，而是缺一个下一步。
原来我不是没有意愿，而是没有提前处理障碍。
```

这种「原来如此」才叫体认。

关键判断：

```text
体认不能靠继续解释获得。
体认靠小规模真实试用。
```

例如，GROW 的体认可能来自一次真实使用：

```text
我卡住了。
我写下：
目标是什么？
现实是什么？
选项有哪些？
我愿意先做哪一步？

写完后发现：
原来我一直卡住，不是因为事情太复杂，
而是我没有把“下一步”压小。
```

这一刻就是体认。

---

## 十二、能力如何形成

能力不是一次体认。

能力来自：

```text
重复调用
```

第一次用 GROW，需要看模板。

第二次用，还需要提醒自己。

多次使用后，遇到「好乱，不知道怎么办」时，可能自然问：

```text
我真正想达成什么？
现在真实情况是什么？
我愿意先做哪一步？
```

这时模型开始变成能力。

能力的标志是：

```text
模型不再作为知识被想起，而是作为问题被自然问出。
```

例如，GROW 内化成能力后，不一定会想：

```text
我要使用 GROW。
```

而是自然问：

```text
我真正要的是什么？
现在真实情况是什么？
我愿意先做哪一步？
```

模型消失了，问题留下了。

这就是能力。

---

## 十三、从理论到能力的训练路径

如果最缺的是体认与能力，下一步不能只是继续听讲。

需要换成训练结构。

路径是：

```text
理论
  -> 程序
  -> 小规模真实使用
  -> 体认
  -> 重复调用
  -> 能力
```

不要从理论直接跳能力。

中间必须经过：

```text
真实使用
```

---

## 十四、训练菜谱：把一个模型练成体认与能力

```text
菜谱：把一个模型练成体认与能力

目标：
让一个模型从“我知道”变成“我用过，并开始自然调用”。

周期：
7 天。

材料：
一个模型。
一个固定模板。
每天一个真实小问题。

步骤：
1. 只选一个模型。
2. 写出它的 4 到 6 个核心问题。
3. 每天找一个真实场景使用 10 分钟。
4. 用完只记录一句反馈。
5. 第 7 天回看：它在哪些场景真的有用？哪里没用？
6. 修改应用卡。
7. 进入下一轮。

完成标准：
至少真实使用 5 次。
每次都有一个实际下一步或实际判断。
第 7 天能说出一句“我现在体会到它的作用是……”。

常见错误：
不要同时练太多模型。
不要把训练变成写长笔记。
不要追求一次用完美。
不要只在脑子里想，要写出来。
不要跳过反馈句。
```

---

## 十五、本阶段核心结论

### 1. 应用不是从理论直接跳到能力

```text
理论
  -> 程序
  -> 体认
  -> 能力
```

每一层都需要不同方式训练。

### 2. 体认来自真实使用

```text
听懂不等于体认。
体认是知识和自己的经验对上。
```

### 3. 能力来自重复调用

```text
模型重复被使用后，才可能从“知识”变成“自然发问方式”。
```

### 4. AI 可以帮你显化，但不能替你体认

```text
AI 可以把理论转成程序。
AI 可以帮助命名隐性判断。
但真实使用、反馈和能力形成仍然必须由人完成。
```

### 5. 模型训练的目标不是背熟模型

真正目标是获得一句属于自己的体认：

```text
我体会到这个模型在我这里的作用是……
```

例如：

```text
我体会到 GROW 的作用，不是帮我制定宏大计划，
而是把混乱压成一个愿意做的小动作。
```
